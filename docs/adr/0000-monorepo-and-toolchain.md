# ADR-0 — Monorepo & toolchain

- **Status:** Accepted (Sprint 0)
- **Context:** build.md §1, §5 Sprint 0

## Decision

One repository, two build worlds joined at the root:

```
kaido/
├─ contracts/   Rust / Soroban — its own Cargo workspace
├─ web/         Next.js 16 app (App Router) + thin BFF route handlers
├─ packages/    sdk · contract-bindings (generated, committed) · config (shared eslint/tsconfig/tailwind)
├─ docs/        ADRs, math derivations, cross-language test vectors
└─ config/      networks.json — static, public network params (no contract ids)
```

- **JS:** pnpm workspaces + Turborepo (`turbo run build|lint|test|typecheck`),
  Node ≥ 22. Workspaces: `web`, `packages/*`.
- **Rust:** a Cargo workspace under `contracts/` driven by **cargo-make**
  (`contracts/Makefile.toml`: `build-wasm`, `optimize`, `test`, `fmt`, `clippy`,
  `bindings`, `deploy`). Toolchain pinned in `contracts/rust-toolchain.toml`
  (stable + `wasm32v1-none`; nightly only in `contracts/fuzz/`, which is
  excluded from the workspace).
- **Stellar CLI** (`stellar contract …`) for build/optimize/deploy/bindings.
- **Dependency hygiene:** `soroban-sdk` pinned (`=25.3.1`) — re-check the
  advisory list before bumping (CVE-2026-26267 re: `#[contractimpl]` name
  collisions). `cargo audit` / `pnpm audit` + Dependabot run in CI.
- **No workspace-level `forbid(unsafe_code)`** on the Rust side: the soroban
  macros emit an internal `#[allow(unsafe_code)]` that a `forbid` rejects
  (E0453). Lint cleanliness is enforced by `cargo clippy -- -D warnings`
  instead; `kaido-math` (a pure crate) still forbids unsafe at the crate level.

## Consequences

- Contracts, SDK and frontend version together; bindings are regenerated by CI
  on a contract diff and a staleness check fails the build if they drift.
- One CI definition per world (`.github/workflows/ci-contracts.yml`,
  `ci-web.yml`) plus a `deploy-testnet.yml`; branch protection on `main`.
- Local dev loop: `make localnet` (Stellar quickstart container) →
  `cargo make --cwd contracts build-wasm` → `pnpm dev`.

## Alternatives considered

- **Polyrepo** (contracts / sdk / web separate): rejected — the
  curve-fit conformance contract between `kaido-math` and `web/lib/curve` and
  the bindings-staleness check are far cheaper to enforce in one repo.
- **Nx instead of Turborepo:** Turborepo is lighter and enough for this graph.
- **`just`/`make` for Rust instead of cargo-make:** cargo-make keeps the task
  graph in Rust-land and is what the build plan specifies.
